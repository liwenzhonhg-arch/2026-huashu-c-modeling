# 论文评审报告

## 总体评价

论文建立了较完整的算力—新能源—储能—电网统一核算框架，能够区分任务瞬时容量占用与按重叠时长计算的能量消耗，四个子问题均有可追溯结果，数值审计也未发现缺少求解出处的数字。尤其值得肯定的是，论文没有把启发式结果包装成 Pareto 解或最优解，并明确披露数学 formulation 与实际 heuristic implementation 的差异。

主要短板在于“优化模型”实际退化为确定性贪心和规则复算：问题二至问题四未实施所述邻域搜索，问题三储能只充不放，问题四固定任务方案，因而多目标优化、储能协同和碳约束响应的实证力度不足。此外，问题一缺少正文所要求的任务甘特图，属于硬性交付物不完整。按国赛标准，当前稿件约处于全国二等奖偏下至三等奖水平；补齐甘特图并增强求解与独立验证后，才有较稳定的二等奖竞争力。

## 具体修改建议

1. 在 `sections/model_solution.tex` 的问题一结果部分补充最后24小时任务甘特图。由于共有538个任务，不宜将全部任务压缩进单张不可读图片；可按区域分面、按任务类型着色，并单独突出第2400至2405小时结清的68个任务。图后应分析拥塞时段、跨小时执行和区域迁移，而不仅说明字段口径。

2. 在问题一预测部分补充区域—任务类型分组的 MAE、RMSE 和 WAPE，并明确哪些分组因分母为零而标记不可用。至少加入朴素滞后、24小时季节性或168小时季节性基线，使固定 Huber 模型的选择具有比较依据；若不补做选模，应将其定位为稳健预测基线，而非暗示其具有模型优势。

3. 将约束审计从“状态为真”扩展为可核验摘要表，报告唯一执行违约数、实时开工违约数、最大GPU超限量、最大IT/设施功率超限量、最大能源平衡残差、最大SOC递推残差、终端SOC最小裕量及所用数值容差。现有 `constraint_audit.csv` 可作为数据源，正文只需列关键汇总值。

4. 明确第2406小时的时间含义。目前既称其为“终端结算时点”，又使用 $S_{r,2406}$ 表示该小时运行后的SOC。应统一说明它代表时点2406的终端状态，还是区间 $[2406,2407)$ 运行后的状态，并相应调整 $\mathcal T_E$、SOC递推范围和终端约束，避免多计算一个结算时段。

5. 问题三应补做至少一个具有充放电动作的可行策略或有界局部搜索实验。当前累计放电为零，储能只把原可售新能源转化为终端库存，使成本增加且不削峰，这只能证明当前规则缺乏有效性，不能充分回答储能协同调度的决策问题。可设置成本、碳排放和峰值的加权或 $\varepsilon$ 约束候选，并与现有规则型方案并列比较。

6. 问题四应让至少部分任务迁移或开工决策随情景重新调整。当前15个情景均保持209个迁移任务、相同时延和服务质量，实质上是固定任务方案下的能源复算。若受运行时间限制，可选取碳约束、新能源下降和新能源波动三个代表情景执行小规模交替邻域搜索，并报告评价次数、终止原因及相对基准改善。

7. 对碳削减水平 $0.1$、$0.2$、$0.3$ 的结果继续保持“启发式内未达到”的表述，不得改写为数学不可行。建议补充基准碳排放、目标上限和候选最小碳排放之间的数值差距，使“未达到”的含义更加明确。

8. 新能源波动灵敏度不应只依赖固定种子2026的单次结果。建议使用多个预先固定种子，报告成本、碳排放和峰值净购电的均值、标准差、分位数及最差情景；这属于代理稳健性验证，不需要不可观测的最优标签。

9. 统一表格精度和单位。成本一般保留到元或两位小数，比例保留4至6位即可，灵敏度百分比不应保留十余位小数。问题四情景表应明确碳排放单位为 tCO$_2$、时延单位为 ms、新能源利用率无量纲。

10. 进一步解释负成本的核算边界。虽然论文已说明其来自售电收入，但累计售电约为132万 MWh、购电仅约40 MWh，结果高度受外送价格和容量设定支配。建议增加售电量占可用新能源比例、外送上限命中率及弃电量，帮助评审判断该数量级是否符合附件情景。

11. 精简重复说明。关于“非Pareto、无最优性证书、未执行邻域搜索”的内容在问题分析、模型求解和模型评价中多次重复。模型章节保留事实，评价章节集中讨论影响，摘要保留一句结论即可。

12. 扩充参考文献。除现有 Huber、多目标优化和MPC文献外，应补充数据中心任务调度、碳感知计算、储能经济调度及启发式邻域搜索的代表性文献，并在相应模型段落中引用。附件数据来源和字段口径也应明确说明。

13. 完善 `sections/appendix.tex`。至少列明 Python 与主要库版本、程序入口、输入文件位置、输出目录、随机种子及复现实验命令，并说明 `code/solution.py` 与根目录 `solution.py` 的关系，防止提交包出现两个版本而产生歧义。

14. 最终编译后检查宽表、长符号表和图片浮动位置，并核对正文是否不超过20页、摘要是否独立成页、所有图表是否在正文首次引用后出现。当前材料不足以确认这些版式要求。
