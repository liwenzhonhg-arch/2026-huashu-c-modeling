# 问题分析

## 题目概述

本题研究六个区域、三类异构 AI 任务、电力系统、新能源、储能与通信网络之间的联合调度。核心是在 GPU、IT 功率、设施功率、网络时延、任务截止时间、区域购售电边界及储能运行边界内，决定任务执行区域、开工时刻以及储能充放电和购售电策略，并评价成本、碳排放、时延、服务质量、新能源利用率、峰值净购电与负荷波动。

运行时域必须分层处理：第 0–2399 小时为任务到达主时域，第 2400–2405 小时仅用于结清此前到达的弹性任务，第 2406 小时不得执行任务，仅用于电力和储能终端结算。任务不可抢占、不可拆分、不可中途迁移；实时推理任务到达即开工，批量推理和 AI 训练任务可以延迟，但必须在时点 2406 前完成。

四问分别对应预测与基础调度、碳感知任务调度、固定负荷下的储能优化以及完整的算—储—电多目标协同优化。问题二至问题四均应使用实际任务与实际逐时参数重新计算，不能直接沿用问题一的预测调度；问题三的任务负荷则由附件明确固定，不得重新优化任务迁移和开工时间。

## 子问题分解

### 子问题 1：GPU 需求统计、短期预测与末端基础调度

- 目标：
  - 按区域和任务类型统计 GPU 需求的规模、分布、时序规律及波动特征。
  - 构建短期预测模型，按建议的数据划分完成训练、调参与最终测试。
  - 基于第 2376–2399 小时的实际到达任务建立基础算力调度方案。
  - 对跨越第 2399 小时的任务使用第 2400–2405 小时收尾时域完成结清。
  - 展示最后 24 小时任务调度甘特图和各区域 GPU 利用率。
- 关键信息：
  - 预测阶段建议使用第 0–2351 小时训练、第 2352–2375 小时调参验证；模型确定后，使用第 0–2375 小时重新训练，并以第 2376–2399 小时为最终测试集。
  - 最后 24 小时的基础调度必须使用实际到达任务，而不是预测值。
  - GPU 容量按任务在小时内的实际重叠时长折算为 GPU-hour。
  - AI IT 功率必须由 `power_mapping.xlsx` 中对应任务类型的单位等效 GPU 功率换算。
  - 调度须同时满足 Available_GPU、Max_IT_Power_MW、Max_Facility_Power_MW、网络时延、到达时间和完成时限。
- 难点：
  - GPU 需求序列可能同时具有趋势、周期性、区域差异、任务类型差异和突发峰值，需防止随机划分造成时间泄漏。
  - 分钟级任务持续时间与小时级资源约束并存，必须准确计算跨小时重叠比例。
  - 不可抢占约束使开工决策具有连续占用效应，末端任务还涉及收尾时域。
  - 甘特图应呈现任务的实际起止时刻、执行区域和任务类型，不能只画小时汇总负荷。

建议统计各区域—任务类型组合的任务数、GPU_Demand 总量与分位数、GPU-hour、平均与分位执行时长、峰值并发 GPU、到达强度、小时/日周期、自相关及区域间相关性。预测目标宜明确为逐小时到达 GPU 需求或 GPU-hour，并以 MAE、RMSE、MAPE/WAPE 等指标分组评价；零值较多时优先采用 WAPE 或 MAE，避免 MAPE 失真。

基础调度可采用混合整数规划或“实时任务优先、截止时间优先、短任务优先”的可行性启发式。实时任务固定在到达时刻开工，只在满足单向网络时延和资源容量的区域中选址；弹性任务在到达后、截止前选择执行区域和连续开工区间。

### 子问题 2：碳感知任务迁移与开工优化

- 目标：
  - 使用第 0–2399 小时实际到达任务及第 0–2406 小时逐时电力参数，联合决定任务执行区域与开工时段。
  - 计算并优化或评价系统运行成本、碳排放、网络时延和新能源利用率。
  - 给出可执行的碳感知调度策略，并报告各项指标及其相对基准的变化。
- 关键信息：
  - 第 2400–2405 小时无新任务，但末端弹性任务的能耗、成本和碳排放仍须计入。
  - 第 2406 小时不得安排任务。
  - AI IT 负荷由任务 GPU 需求、小时重叠比例和统一功率映射计算；区域总 IT 负荷还应加入不可迁移的 `NonAI_IT_Load_MW`。
  - 设施负荷为总 IT 负荷乘区域 PUE，不能仅对 AI 负荷乘 PUE。
  - 碳排放按电网购电功率乘碳强度累计。
  - 新能源利用率按“直接消纳新能源＋新能源充电＋新能源外送”除以可用新能源累计计算。
  - 通信部分只考虑 `network_latency.xlsx` 中的单向时延，不建立带宽、迁移数据量、传输能耗或费用模型。
- 难点：
  - 任务不可拆分且不可抢占，区域和开工时间均为离散决策，形成大规模混合整数优化。
  - 成本、碳排放、时延和新能源利用率的量纲不同且相互冲突，不能未经归一化直接加权。
  - 实时、批量、训练任务的时延敏感性不同，需要在硬 SLA 约束之外设计合理的分类评价。
  - 新能源直接消纳和购电量必须由逐时能量平衡共同决定，不能仅按新能源出力大小选择区域。

可建立二元变量 \(x_{i,r,s}\)，表示任务 \(i\) 是否在区域 \(r\)、时刻 \(s\) 开工。对每个任务要求唯一选址和唯一开工；实时任务令 \(s=ArrivalHour_i\)，其他任务满足 \(s\ge ArrivalHour_i\) 且完成时刻不超过其 `LatestFinishHour` 和系统时点 2406。利用预先计算的小时重叠系数形成 GPU-hour 与 AI IT 负荷，再施加区域逐时 GPU、IT 功率和设施功率约束。

多目标处理可采用 ε-约束法生成 Pareto 前沿：以运行成本为主目标，分别对碳排放、平均或高分位网络时延及新能源利用率设置约束；也可在无量纲化后使用加权和进行敏感性分析。调度策略应区分任务类型：实时推理优先在低时延可行区域执行；批量推理在时延、价格与低碳窗口之间折中；训练任务重点迁往低价、低碳或高新能源区域并利用时间弹性错峰执行。

### 子问题 3：给定负荷下的储能协同优化

- 目标：
  - 在任务调度和逐时 IT 负荷固定的前提下，优化各区域逐时充电、放电、购电、售电、新能源直接消纳与弃电策略。
  - 比较配置储能前后或基准策略与优化策略下的运行成本、碳排放、区域峰值净购电功率和负荷波动程度。
  - 给出逐区域、逐时储能充放电策略及终端 SOC。
- 关键信息：
  - 固定 IT 负荷取 `Baseline_AI_IT_Load_MW + NonAI_IT_Load_MW`，设施负荷按该总 IT 负荷乘区域 PUE。
  - 不得重新优化任务迁移与开工时段。
  - `InitialSOC_MWh` 是第 0 小时运行前的唯一初始状态；不得将第 0 小时重新归零，也不得把初始 SOC 作为待估参数。
  - `region_time_data.xlsx` 中 `SOC_MWh` 是每小时运行后的基准状态，仅用于基准对比，不替代优化模型的初值。
  - SOC 递推为
    \[
    SOC_{r,t}=SOC_{r,t-1}+\eta^c_r ChargePower_{r,t}
    -\frac{DischargePower_{r,t}}{\eta^d_r}.
    \]
  - 终端状态必须满足 \(SOC_{r,2406}\ge InitialSOC_r\)。
  - 还需满足 SOC 上下限、最大充放电功率、最大购售电功率及外送上限。
- 难点：
  - 电价套利、削峰、减碳和促进新能源消纳可能给出不同的充放电时机。
  - 若允许电网充电，碳排放必须按总 `GridPurchase_MW` 计算，不能遗漏充电购电。
  - 需要定义可复现的负荷波动指标，例如净购电功率的标准差、方差或相邻时段爬坡绝对值之和。
  - 必须防止同一时段无意义的同时充放电或同时购售电；若价格结构和效率不足以自然排除，应加入互斥变量。

该问可建立线性规划或混合整数线性规划。能量平衡应逐区域逐小时满足：
\[
GridPurchase+AvailableRenewable+DischargePower
=TotalLoad+ChargePower+GridSell+Curtailment.
\]
其中充电应进一步拆为新能源充电和电网充电，以便严格计算新能源利用率与电网购电成本。峰值净购电可用辅助变量线性化，负荷波动可采用绝对爬坡量线性化，或采用方差构成二次规划。

### 子问题 4：多区域算—储—电多目标联合优化及情景比较

- 目标：
  - 联合决定任务迁移、任务开工、储能充放电、新能源分配以及区域购售电。
  - 在系统运行成本、碳排放、网络时延、服务质量、新能源利用率和区域峰值净购电之间进行权衡。
  - 比较不同碳约束、电价机制和新能源波动场景下的最优策略及指标变化。
- 关键信息：
  - 继承问题一、二中的任务不可抢占、容量、功率、网络时延与完成时限约束。
  - 继承问题三中的能量平衡、SOC 动态、初始 SOC、终端 SOC、充放电功率和购售电边界。
  - 问题四仍以实际任务、实际逐时电力参数和统一功率映射重新计算。
  - 不建立线路潮流、网络带宽、迁移数据量、传输能耗或传输费用模型。
  - 服务质量应由题面已有信息构造，如截止时间满足率、实时任务即时开工满足率、SLA 时延满足情况或弹性任务等待时间，不能引入无数据支持的服务指标。
- 难点：
  - 任务二元决策与储能连续决策跨越 2407 个电力时点，模型规模大。
  - 六个目标之间存在显著冲突，需要给出 Pareto 解或明确、可解释的偏好规则。
  - 情景变化不仅影响目标值，还可能改变任务迁移方向、开工窗口、储能循环和购售电行为。
  - 碳约束、电价机制与新能源波动场景必须在一致的任务集、约束与评价口径下比较，否则策略差异不可归因。

建议采用分层或滚动时域求解：先筛除不满足时延、截止时间或容量下界的任务—区域—开工组合，再按日或滚动窗口优化，同时为跨窗口任务保留连续占用状态。最终可使用 ε-约束法获得成本—碳排放—峰值净购电等目标的 Pareto 解，并通过统一的归一化指标或理想点距离选择折中方案。

情景设计至少包括：

- 碳约束：无额外碳约束、相对基准分级减排约束、严格碳预算。
- 电价机制：原始分时电价、峰谷价差扩大或缩小、售电价格变化。
- 新能源波动：基准出力、整体下降或上升、波动增强；场景变换后保证可用新能源非负。
- 每个场景报告成本、碳排放、网络时延、服务质量、新能源利用率、各区域峰值净购电、迁移任务量和储能循环特征。

## 子问题依赖关系

- 问题一的统计与预测可独立开展；其预测结果仅用于预测评价，最后 24 小时调度使用实际任务。
- 问题二不依赖问题一的预测结果，但可复用问题一形成的任务重叠计算、基础调度模型及统计认识。正式计算必须以实际任务和实际逐时参数重新进行。
- 问题三可与问题一、二并行，因为题面已固定其 AI IT 负荷和 NonAI IT 负荷；它不使用问题二优化后的任务调度。
- 问题四依赖前三问形成的任务调度约束、碳感知目标构造、储能动态和评价体系，但须重新进行联合优化，不能简单拼接前三问结果。

## 数据分析要点

1. **表结构与口径核验**  
   读取所有工作簿的字段说明、说明和备注工作表，确认单位、时间索引、区域集合、任务类型编码、缺失值和重复记录。尤其核对 `power_mapping.xlsx` 的任务类型映射以及 `region_time_data.xlsx` 是否包含 `NonAI_IT_Load_MW`、购售电上限等正文引用字段。

2. **时间覆盖与边界**  
   `workload_trace.xlsx` 应覆盖到达小时 0–2399；`region_time_data.xlsx` 应覆盖区域—小时 0–2406。任务在 2400–2405 可以继续执行，但不得占用第 2406 小时。需要统一“完成时点”和“占用小时”的边界定义，避免把在时点 2406 完成误写成占用第 2406 小时。

3. **初始状态处理**  
   问题三、四必须以 `storage_information.xlsx` 的 `InitialSOC_MWh` 作为第 0 小时运行前状态，构造绝对 SOC 轨迹。不得把首行 SOC 重新归零，也不得将已知初值估计化。附件中的逐时 `SOC_MWh` 是基准状态轨迹，只用于核验和对比。

4. **任务重叠换算**  
   `EstimatedDuration_min` 可能不是整小时。应根据实际起止时刻计算每小时重叠时长，并据此形成 GPU-hour 和 AI IT 负荷。不可将所有触及某小时的任务都按完整一小时占用，也不可拆分执行。

5. **预测数据防泄漏**  
   仅按时间顺序划分训练、验证和测试集；所有标准化、特征选择和超参数选择只能基于训练/验证区间。最终测试结果不得参与模型选择。应分别报告区域、任务类型及总体误差。

6. **负荷和功率一致性**  
   问题二、四中：
   \[
   AIITLoad=\sum GPU_Demand\times Overlap\times GPU\_Power,
   \]
   \[
   ITLoad=NonAIITLoad+AIITLoad,\quad TotalLoad=ITLoad\times PUE.
   \]
   问题三则固定使用 `Baseline_AI_IT_Load_MW + NonAI_IT_Load_MW`。附件中的基准 `IT_Load_MW` 不应在问题二、四中整体固定。
