# 模型验证报告

## 总体评价
需修改。任务重叠、GPU-hour、功率映射、购售电互斥及非负峰值等修正基本正确，量纲总体一致，也没有错误使用不可观测的监督学习标签或虚构已完成的拟合结果。但问题三、问题四的若干硬约束和指标仅以“保持原式”“定义保持不变”引用未提供内容，服务质量指标未形成完整方程，必答结果键和文件名也未实际列出；因此当前模型不能唯一实现并保证完整交付，严重程度为 `block`。

## 逐项检查

### 公式正确性
- [通过] 式(1)正确计算任务与小时区间的连续重叠时长。
- [通过] 式(4)将 GPU 功率乘重叠时长后除以 \(\Delta t\)，得到小时平均功率；式(5)、式(10)的 GPU-hour 量纲也正确。
- [通过] 问题二的新能源分流与无储能供能平衡可以闭合；新能源充电为零时，新能源利用率分子使用直接消纳与外送符合附件口径。
- [通过] 式(13)把峰值净购电定义为 \(\max_t\max(0,N_{rt})\)，避免全时段净外送时出现负峰值。
- [问题] 问题四使用 \(Q_{\rm service}\)、\(\epsilon_Q\)、\(\bar W\)、\(W_{\rm ref}\) 和 \(S_W\)，但没有给出完整服务质量函数、等待时间定义、各分项权重及重新归一化方程。“服务质量定义保持不变”无法引用到本次提交中的任何完整原式。
- [问题] 式(15)只是忽略电网进口、设施功率和可用能源限制后的必要条件，不能“保证终端 SOC 仍可达”。模型正文对此表述较谨慎，但结构化方程中的“保证”结论数学上过强。
- [问题] 式(12)正文定义 \(M_{rt}^{sell}\)，结构化模型却写成 \(M_P_r\)，且 \(S_r^{\max}\) 未明确绑定附件中的 `SellLimit_MW`。这会造成实现口径不唯一。

### 量纲一致性
- [通过] 成本、碳排放、SOC递推、网络时延加权平均、GPU利用率和负荷功率的主要量纲一致。
- [通过] 式(15)中功率乘时长得到 MWh，与SOC量纲一致。
- [问题] \(d_i\) 允许非整数小时，而开工时刻 \(s\) 是否必须取整数小时没有在变量域中明确声明。虽然假设称按小时选择，但应在正式集合中写明 \(s\in\mathbb Z\)。

### 约束完整性
- [通过] 任务唯一分配、到达时间、截止时间、网络时延、GPU容量、IT功率和设施功率约束均已纳入统一内核。
- [通过] 实时任务固定到达即开工，所有任务不得占用第2406小时。
- [问题] 问题三仅写“能源分流、SOC和充放电互斥保持原式”，但本次模型没有完整列出以下硬约束：\(E_{r,-1}=E_r^0\)、逐时SOC上下限、充放电功率上限、二元互斥的具体不等式、外送上限，以及所有能源流的非负域。结构化部分同样仅写“充放电互斥”。这些是题面明确要求的物理硬约束，缺失会直接影响可行域。
- [问题] 问题四声称继承问题三全部约束，但问题三本身未完整定义，因此联合模型仍不闭合。
- [问题] 问题二至四使用 \(P_{rt}^{grid,\max}\) 和 \(P_{rt}^{export,\max}\)，却没有明确将其分别绑定到附件中的区域购电、外送硬边界，也未说明不存在储能区域时变量应如何固定。
- [问题] 购售互斥约束的售电大 \(M\) 应直接采用附件相应时段或区域的实际外送上限；当前额外引入未定义的 \(S_r^{\max}\)。

### 参数合理性
- [通过] \(B_{\rm total}=300\rm\,s\)、\(D_{\rm search}=t_{\rm start}+285\rm\,s\)、\(T_{\rm tail}=15\rm\,s\) 符合给定单轮执行预算。
- [通过] 未把未搜索的参数范围冒充文献结论，也未声称已经获得拟合参数、RMSE、\(R^2\) 或最优值。
- [问题] 岭回归特征向量 \(\mathbf z_{rkt}\)、候选 \(\lambda\) 集合和验证选择规则没有封闭定义，预测模型尚不能完全复现。
- [问题] 三组“联动预算”的具体构造公式未给出。多个目标的25%、50%、75%究竟相对哪个理想值和劣值插值不明确。

### 可求解性
- [通过] 在补齐缺失定义后，任务调度与能源系统可建立为MILP或含线性化绝对值的混合整数模型。
- [通过] WAPE、GPU利用率和新能源利用率均设置了零分母分支，不会因此产生 NaN/Inf。
- [问题] 固定候选启动前仅按剩余时间设置不超过30秒的上限，却没有为问题一必答调度、问题二和问题三扫描、问题四基准与27个情景分别预留可执行预算。前序求解可能耗尽285秒搜索期，使后续必答子问题全部未启动。
- [问题] “不缩减候选集”与“截止后候选不启动”逻辑冲突。当前没有规定如何在共享预算内保证各必答问题至少产生一个完整可行方案，因此不能保证题目要求的四问输出。
- [问题] 服务质量约束和三组联动预算未定义，使问题四即使调用求解器也无法唯一构造。

### 数据可观测性
- [通过] 需求预测使用实际GPU需求作为标签；调度与储能最优方案没有真实标签，模型正确改用约束残差、守恒和求解状态验证，没有使用准确率、召回率或混淆矩阵。
- [通过] 对WAPE零分母及新能源利用率零分母设置不可用状态，处理合理。
- [问题] “保持原9项输出及文件名”“保持原7项输出”等未列出具体结果键和文件名。当前文本无法判断是否保存了题面要求的第2376–2399小时逐任务方案、甘特图数据、区域GPU利用率、储能逐时策略及各场景比较结果。

### 结果常识性
- [通过] 禁止同时充放电和同时购售电符合工程常识；非负峰值定义也合理。
- [通过] 实时任务即时开工、网络时延限制、不可抢占以及终端SOC不透支均符合题意。
- [问题] 若SOC上下限、充放电功率和区域购售电上限只停留在“保持原式”而未实际进入实现，求解器可能产生超容量储能动作或超边界购售电，所得结果不具工程可行性。

## 修改建议
1. 完整写出问题三的初始SOC、逐时SOC上下限、充放电功率上限、充放电互斥、购售电上限、外送上限、非负域和终端SOC约束；问题四明确逐项继承这些方程。
2. 给出 \(Q_{\rm service}\) 的完整可计算定义，包括等待时间、按期完成、实时即时开工、时延SLA等分项及权重；定义空集合和零参考值分支。
3. 将售电大 \(M\) 统一写成附件实际外送上限，统一 \(M_{rt}^{sell}\) 的名称，并删除或明确定义 \(S_r^{\max}\)。
4. 明确 \(s\) 为整数小时，封闭定义岭回归特征、\(\lambda\) 候选和验证选择规则。
5. 写出三组联动预算的确定公式，而不只写25%、50%、75%。
6. 原样列出每一问要求的结果键和文件名，尤其保留逐任务调度、时刻、执行区域、开工与完成时间、甘特图数据、GPU利用率、逐时储能策略和场景比较结果。
7. 为共享300秒预算制定分阶段硬配额或可证明执行完全部必答工作的调度规则；不能仅让前序候选占用全部搜索时间后把后续问题标记为未启动。
8. 将式(15)描述为“仅基于最大充电功率的必要筛查条件”，不得宣称其单独保证SOC可达；最终仍以完整能源约束和 \(E_{r,2406}\ge E_r^0\) 判定。
