# 模型验证报告

## 总体评价
需修改。模型已较好地区分瞬时容量约束与小时重叠能量，并覆盖任务唯一性、时延、截止时间、储能 SOC、购售电边界及有限指标检查；但预测模型缺少题面要求的全数据重训练步骤，实时任务的缺省完成时限未封闭定义，且储能模型未落实其假设中要求的购售电互斥条件。这些问题可能分别造成测试口径错误、候选集合不可计算和能源套利，因此当前不能直接进入正式求解。

## 逐项检查

### 公式正确性
- [通过] 重叠时长 \(\omega_{it}(s)\)、任务唯一执行、SOC 递推、成本和碳排放公式在量纲与符号上正确。
- [通过] 在整数小时开工条件下，\(\chi_{it}(s)\) 对每个被任务触及的小时计入完整 GPU 和 IT 功率，可用于检查小时内峰值；\(\omega_{it}(s)\) 则用于能量结算，两种口径没有混用。
- [问题] 问题三、四仅给出了充放电互斥式（41），没有给出购电与外送互斥约束。模型假设第20条明确要求在价格不能自然排除套利时增加互斥约束，但数学模型没有落实。
- [问题] Huber 损失 \(\rho_{\delta_H}\) 未显式定义。虽然不妨碍理解，但实现前应补充其分段公式。
- [问题] 电价情景式（51）未检查变换后购电价格是否非负。若原始价格波动较大，\(\kappa=1.2\) 可能产生负价；应明确负价是否合法或给出附件驱动的检查规则。

### 量纲一致性
- [通过] GPU、MW、MWh、元和 tCO2 的主要公式量纲一致；式（11）由 MW/GPU、GPU 和小时得到 MWh。
- [通过] SOC 递推中充放电功率均乘 \(\Delta t\)，效率作用方向正确。
- [通过] 网络时延、服务质量及新能源利用率指标的分子、分母口径一致。
- [问题] 固定残差容差写成 \(10^{-6}\max(1,\text{约束尺度})\)，但不同约束分别具有 GPU、MW、MWh 等量纲。“最大约束残差”汇总前应先按各自尺度归一化，不能直接比较不同单位的原始残差。

### 约束完整性
- [通过] 已包含任务唯一性、到达时间、网络时延、完成时限、2406小时禁占用、GPU、IT功率和设施功率约束。
- [通过] 已包含新能源分流、区域购售电上限、SOC上下限、充放电效率、终端SOC和充放电互斥约束。
- [问题] \(f_i^{late}\) 被直接用于所有任务的候选集合，但数据字典说明该字段“主要用于批量推理和训练任务”。若实时任务该字段为空，式（3）的 \(\min(f_i^{late},2406)\) 将不可计算。应定义
  \[
  \bar f_i=
  \begin{cases}
  \min(f_i^{late},2406),&f_i^{late}\text{ 有效},\\
  2406,&f_i^{late}\text{ 缨失且任务为实时任务},
  \end{cases}
  \]
  并对弹性任务缺失截止时间结构化停止。
- [问题] 问题三、四缺少条件性的购电—外送互斥约束。例如价格不能排除套利时，应增加二元变量 \(v_{rt}\)，约束
  \[
  B_{rt}\le G_r^{import,max}v_{rt},\qquad
  S_{rt}\le \bar S_r(1-v_{rt}).
  \]
  若选择允许二者并存，则必须证明外送完全来自当期新能源，且购电不会替代本可直接消纳的新能源以获取价差。
- [问题] 问题一最后24小时调度应明确计入此前到达但在2376小时后仍运行的任务，否则2376—2399小时容量检查可能遗漏存量占用。

### 参数合理性
- [通过] PUE、效率、SOC、功率和时延参数均取自附件，没有把未搜索的“典型参数范围”当作文献证据。
- [通过] 10000、2000等是预声明的启发式检查规模，模型没有将其宣称为全局优化证明。
- [问题] \(R_{rt}^{res}\) 被称为“剩余新能源能量”，但符号采用功率变量形式。实现时应统一为 MWh，或明确因 \(\Delta t=1\) 数值相等但单位仍需转换。
- [问题] 七情景的“实际检查任务数”必须记录真实完成数，不能在达到共享截止时间后仍填入预设的2000或10000。

### 可求解性
- [通过] 四个子问题均可由确定性预测、可行调度、局部搜索和前向SOC递推实现；模型诚实标记 `scenario-feasible` 和 `global_optimality=not_certified`。
- [通过] 共享墙钟固定为300秒，并为最终验证及输出保留15秒，符合单轮执行预算要求。
- [问题] 问题一明确把训练样本固定为 \(168,\ldots,2351\)，完成验证选型后却没有执行题面要求的“以0—2375小时数据重新训练”。如果直接用原训练模型测试2376—2399，将不符合指定预测流程。
- [问题] “训练只用 \(t=168,\ldots,2351\)”还会与重新训练要求冲突。应区分 `selection_fit` 与 `final_fit`：模型选择阶段训练至2351，选定超参数后以0—2375可构造的全部有效样本重新拟合，再递归预测2376—2399。
- [问题] 固定阶段截止规则没有说明某阶段提前结束后的剩余时间能否供后续阶段使用。应采用共享绝对截止时间，并在每个候选开始前检查是否仍有完成该候选和恢复状态的预算。

### 数据可观测性
- [通过] 没有使用不存在的最优调度标签、用户满意度标签，也没有错误采用准确率、召回率或混淆矩阵。
- [通过] WAPE、相关系数和ACF均设置了零分母、常数序列及样本不足时的不可用状态。
- [通过] 未执行外部搜索的证据状态被如实保留，模型没有声称已取得文献参数或已完成数值拟合。
- [问题] `LatestFinishHour`、电价和任务字段的缺失值处理需要形成逐字段可执行门禁；当前只有一般性的“不自动补零”原则，尚不足以保证候选集合和情景变换全部有限。

### 结果常识性
- [通过] 禁止同时充放电、限制GPU/IT/设施容量、要求终端SOC不透支以及禁止任务占用2406小时，符合工程常识。
- [问题] 允许同小时购电并外送新能源可能造成“购低价电供负荷或充电、同时售出新能源”的账面套利。模型虽然要求报告该现象，但报告不能替代约束或明确的市场规则。
- [通过] 碳约束未达到时输出 `target_infeasible_within_declared_heuristic` 并排除推荐，避免把启发式失败伪装为可行解。
- [问题] “旧版结果存在具体超限小时数”的表述属于既往运行证据，而本次 model 阶段未运行代码。若这些数字没有随输入提供的可追溯下游报告，正式文稿中应改为“旧结果标记为作废，待代码阶段复核”，不得把其视为本轮已验证结果。

## 修改建议
1. 将预测流程明确拆成模型选择拟合与最终重训练：验证选型后，使用截至2375小时的全部有效历史样本重新拟合选定模型，再递归预测2376—2399。
2. 为实时任务定义缺失 `LatestFinishHour` 的确定性回退规则；弹性任务关键截止字段缺失时结构化停止，禁止让 NaN 进入候选集合。
3. 在问题三、四落实购电与外送的互斥约束，或给出基于附件价格和新能源分源的可执行无套利判定。
4. 明确最后24小时容量核算包含2376小时前已开工且仍在运行的任务。
5. 对GPU、MW、MWh等约束分别归一化残差，再汇总 `max_constraint_residual`。
6. 将未经本轮代码执行支持的具体超限计数标记为历史输入证据或 `pending_code_execution`。
