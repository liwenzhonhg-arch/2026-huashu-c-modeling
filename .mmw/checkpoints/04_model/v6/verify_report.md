# 模型验证报告

## 总体评价
需修改。模型在任务重叠计量、功率—能量换算、SOC递推、有限输出、预测标签可观测性和终端状态约束方面总体严谨，也没有把不存在的最优调度标签用于准确率、召回率或混淆矩阵验证。但当前模型仍存在会改变最终结论的关键问题：问题四的折中解归一化没有统一最小化方向，可能把新能源利用率和服务质量越高的方案评价得越差；滚动时域模型要求每个窗口求解覆盖全部剩余时域的整数终端延续，且四问、标定、Pareto扫描和输出共用300秒预算，缺少预算内可执行的候选压缩与粗细求解规则；问题二的外送上限还错误依赖仅供问题三、四使用的储能附件参数。这些问题会影响折中方案正确性或导致正式必答结果无法在运行合同内产生，故判定为 `block`。

## 逐项检查

### 公式正确性
- [通过] 式(1)–(2)正确计算任务与小时区间的连续重叠时长及平均占用比例；后续GPU平均占用和AI功率使用无量纲比例，逻辑一致。
- [通过] 式(40)–(43)的新能源分流、负荷平衡和SOC递推可以合并为附件统一能量平衡，没有重复计算新能源充电。
- [通过] 式(51)–(56)认识到辅助变量 \(q_{rt}\) 在成本目标下未必等于绝对变化，并要求从最终轨迹复算，处理正确。
- [问题] 式(73)–(74)没有先把所有评价指标统一转换为“越小越好”。成本、碳、时延和峰值是最小化指标，但新能源利用率、服务质量是最大化指标。若直接对后两者使用
  \[
  z=(F-F^{best})/(F^{worst}-F^{best}),
  \]
  而仍以最小 \(D_m\) 选方案，可能反向奖励低新能源利用率或低服务质量，导致问题四折中方案失效。
- [问题] 问题一式(6)将所有任务假定在到达时刻 \(a_i\) 开始后计算，并称为“实际运行GPU-hour”。对允许延后的批量推理和训练任务，该量实际是“按到达立即执行口径的工作量”，不是可观测的实际运行轨迹。公式本身可作为需求统计，但名称和解释必须更正。

### 量纲一致性
- [通过] GPU容量采用 \(g_i\phi_{it}\)，单位为等效GPU；功率采用 \(g_ip_k\phi_{it}\)，单位为MW；成本、碳排放、SOC和吞吐量均显式乘以 \(\Delta t\)，量纲一致。
- [通过] 网络时延均值、等待时间归一化、WAPE、新能源利用率和服务质量的量纲处理正确。
- [通过] EFC采用总充放电吞吐量除以 \(2S_r^{cap}\)，结果为无量纲循环次数，且零容量分支不会产生NaN或Inf。

### 约束完整性
- [通过] 任务唯一执行、到达时间、实时即时开工、网络时延、完成时限、GPU容量、IT功率、设施功率及不得占用第2406小时等主要约束已经保留。
- [通过] 储能模型包含SOC上下限、充放电功率、效率、充放电互斥和终端SOC约束。
- [问题] 问题二定义 \(E_r^{max}=\min(X_r^{grid},X_r^{sell})\)，其中 \(X_r^{sell}\) 来自 `storage_information.xlsx`；但题面数据表明确该附件只用于问题三和问题四。问题二不含储能，其外送硬约束应直接使用 `region_time_data.xlsx` 中的 `MaxGridExport_MW`。否则可能因不存在或不适用的储能外送参数收紧问题二可行域。
- [问题] 模型把题面已经明确的新能源富余外送口径再次设为“待确认并可能停止”。附件已说明 `GridSell_MW` 是新能源富余外送，并给出新能源利用率和统一平衡式，因此无需因该事项停止问题二；只需禁止电网购电直接转售并保持售电量属于新能源分流即可。
- [通过] 同时购售电不必一概禁止：在电网供负荷与新能源富余外送并存时可以物理合理。当前分源变量能够表达该情形，关键是不得允许电网电量进入售电变量。

### 参数合理性
- [通过] PUE、GPU功率映射、网络时延、购售电边界和储能效率均指定从附件读取，没有把未搜索的“典型参数范围”冒充文献证据。
- [问题] \(\alpha,\beta\)、各类 \(\varepsilon\) 网格及折中权重尚无固定值、归一化规则或封闭生成方法。允许在代码阶段确定数值，但必须在求解前固定并写入元数据，否则不同目标的数量级会任意改变结论。
- [问题] \(H,\Delta,\tau\) 只写为“代码阶段固定”，但没有给出受300秒总预算约束的封闭选择规则。它们直接决定模型规模和残差判定，应至少给出有限候选集合及超时降级规则。

### 可求解性
- [问题] 问题二和问题四要求每个滚动窗口都建立覆盖“所有剩余任务至第2405小时”的整数终端延续方案。这在长达2406小时、包含区域和开工时刻组合的不可抢占任务模型中，实质上会在每个窗口重复求解接近全时域的MILP。
- [问题] 执行合同又要求预测标定、问题一、问题二全部参照解与ε网格、问题三、问题四、复算和文件输出共同在300秒内完成。模型没有预声明候选变量筛选、固定的有限Pareto网格规模、每问时间配额或可执行的粗细求解降级规则，因此不能保证在共同截止前完成一次正式求解。
- [问题] 仅规定“候选启动前检查截止并中断”不能解决问题，因为可能在产生问题二至四必答输出前耗尽预算。应把任务候选压缩、滚动窗口数量、每组最多候选数和各阶段硬截止纳入模型合同。
- [通过] 若忽略上述规模问题，各子模型均可表示为MILP，有限输出和最终残差复算规则也明确。

### 数据可观测性
- [通过] 预测标签 \(D_{rkt}\) 由附件实际到达任务聚合，真实可观测；MAE、RMSE和WAPE适用。
- [通过] WAPE零分母和相关系数的常数序列、样本不足分支均输出 `null/unavailable`，不会产生NaN、Inf，也不会把不可计算或负相关误称为验证有效。
- [通过] 模型明确承认调度和储能不存在真实最优动作标签，没有错误使用准确率、召回率或混淆矩阵。
- [通过] 拟合误差、最优值、运行时间和最优间隙均保留为代码阶段计算，没有在未运行代码时声称已经验证通过。
- [问题] 式(6)的“实际运行GPU-hour”不可由任务到达数据直接得到，因为弹性任务实际开工时刻尚未观测；应改名为“到达工作量GPU-hour”或在得到调度结果后按 \(x_{irs}\) 重新计算运行GPU-hour。

### 结果常识性
- [通过] 模型包含GPU、IT功率、设施功率、网络时延、任务截止、购售电功率、SOC及终端能量等现实约束，没有明显允许无限套利或储能透支。
- [通过] 实时任务即时开工，训练和批量任务承担主要迁移与等待调节，符合题面业务逻辑。
- [问题] 若不修正式(73)–(74)的目标方向，最终推荐方案可能偏向更低的新能源利用率和服务质量，违反多目标权衡的基本含义。
- [问题] 以不可执行的全尾部整数证书作为每个窗口的硬条件，可能使模型在正常规模输入下只产生结构化超时而不能给出题目要求的调度、能源策略和情景结果。

## 修改建议
1. 将所有Pareto指标统一为损失方向后再归一化。对最小化指标使用
   \[
   z_{jm}=\frac{F_{jm}-F_j^{best}}{F_j^{worst}-F_j^{best}},
   \]
   对最大化指标使用
   \[
   z_{jm}=\frac{F_j^{best}-F_{jm}}{F_j^{best}-F_j^{worst}},
   \]
   或先定义 \(-U_{RE}\)、\(-Q_{service}\) 为最小化目标，并明确 \(F^{best}\) 与 \(F^{worst}\) 的方向。

2. 问题二的外送上限改为
   \[
   0\le E_{rt}^{sell}\le \mathrm{MaxGridExport\_MW}_{rt或r},
   \]
   不引用 `storage_information.xlsx` 的 `SellLimit_MW`；问题三、四再按题面字段含义决定是否取两个有效上限的最小值。

3. 删除问题二不必要的 `energy_source_accounting_unconfirmed` 停止条件。附件已经确认售电为新能源富余外送；模型应直接通过新能源分流式保证 \(E^{sell}\) 只能来自可用新能源。

4. 将式(6)更名为“按到达立即执行口径的GPU工作量”，或改为基于调度变量的
   \[
   H_{rkt}^{run}=\sum_{i:k_i=k}\sum_s g_i\omega_{it}(s)x_{irs}
   \]
   后再称为实际运行GPU-hour。

5. 重构滚动延续证书，使其在300秒合同内可执行：详细窗口使用整数任务变量；远期延续采用预声明的候选压缩或必要容量包络，最终再用固定粗细网格和完整轨迹复算验证。不得要求当前运行接口不具备的形式化区间证书。

6. 在求解前固定有限的 \(H,\Delta,\tau\)、ε网格数量、候选筛选规则和每阶段墙钟配额，并确保问题二固定扫描、问题三、问题四、复算及输出都计入共同的285秒搜索截止。若预算不足，应按预声明优先级减少Pareto候选，而不是在必答结果产生前任意耗尽预算。

7. 明确 \(\alpha,\beta\) 的量纲归一化方式，并为最大化指标、零范围指标和权重重归一化给出统一实现口径。
