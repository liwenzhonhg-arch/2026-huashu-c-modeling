# 模型验证报告

## 总体评价
需修改。模型整体上较完整地区分了瞬时容量与小时能源结算，储能 SOC、购售电互斥、终端状态、可观测性和有限指标处理也基本正确；但问题一的预测特征在训练初期存在未定义滞后项，任务开工时刻的离散定义不完整，且前序跨界任务所依赖的前序调度方案没有给出可执行的生成规则。这些问题会使预测模型或末端调度无法确定计算，因此总体判定为 `block`。

## 逐项检查

### 公式正确性
- [通过] 重叠时长
  \(\omega_{it}(s)=\max\{0,\min(t+1,s+h_i)-\max(t,s)\}\)
  能正确计算任务与小时区间的交叠。
- [通过] 使用 \(\chi\) 检查瞬时 GPU、IT 和设施功率容量，使用 \(\omega\) 计算 GPU-hour、MWh、成本和碳排放，避免了分数小时任务被按整小时结算。
- [通过] SOC 递推中充电乘以 \(\eta_c\)、放电除以 \(\eta_d\)，方向正确。
- [通过] 问题三、四的能源流分源方程与新能源分配方程联立后不存在重复计算电网充电或新能源充电的问题。
- [问题] 式(23)包含 \(D_{rk,t-1},D_{rk,t-2},\ldots,D_{rk,t-168}\)，但训练区间从 \(t=0\) 开始，未定义 \(t<0\) 的历史需求，也没有声明训练样本从 \(t=168\) 开始或采用何种固定初始化。现有目标函数在训练初期没有定义。
- [问题] 式(5)仅写出关于 \(s\) 的不等式，没有明确 \(s\in\{0,\ldots,2405\}\cap\mathbb Z\)。虽然文字称开工时刻按小时粒度选取，但数学模型中的候选集合仍可能被解释成连续集合，与二元变量 \(x_{irs}\) 的有限 MILP 索引不一致。

### 量纲一致性
- [通过] \(g_ip_k^{GPU}\omega_{it}(s)\) 的量纲为 MWh，除以 \(\Delta t\) 后为 MW。
- [通过] 设施负荷由 IT 功率乘无量纲 PUE 得到，量纲仍为 MW。
- [通过] 成本、碳排放、SOC 递推、峰值和爬坡量的量纲一致。
- [通过] GPU-hour 加权平均时延式(41)的结果量纲为 ms。
- [通过] 新能源利用率、服务质量和归一化候选损失均为无量纲。

### 约束完整性
- [通过] 已包括唯一执行、到达时刻、实时任务即时开工、网络时延、截止时间、不可抢占、瞬时 GPU、IT 功率、设施功率和第2406小时禁占用约束。
- [通过] 已包括购售电上下限及互斥、储能充放电功率及互斥、SOC 上下限和终端 SOC 约束。
- [通过] 问题二明确禁用储能；问题三固定附件给定负荷，不重新调度任务，符合题面边界。
- [问题] 问题一末端调度依赖“已审计的前序方案” \((r_i^0,s_i^0)\)，但模型没有定义该方案来自附件、基础调度模型还是对第0–2375小时任务的预先求解，也没有给出生成它的目标和确定性规则。因而式(30)–(35)中的前序跨界占用不能由当前模型直接计算，可能遗漏已在2376小时前开工但仍在运行的任务。
- [问题] 应在所有任务候选集合中显式规定有限整数开工网格，并明确只生成满足 \(\omega_{i,2406}(s)=0\) 的候选，以使“第2406小时不执行任务”在模型层直接闭合，而不只依赖完成时间的文字解释和事后审计。
- [通过] 多个优化子问题声明共享 \(300\) 秒墙钟预算、预留 \(15\) 秒终检，并在候选启动前检查统一截止，没有把完整执行上限分别重复分配给问题三和问题四。

### 参数合理性
- [通过] Huber 参数和正则参数均采用预声明有限网格，没有把未搜索的文献范围写成既有证据。
- [通过] PUE、GPU功率、容量、价格、碳强度、储能效率和购售电边界均要求从附件读取，没有在模型阶段虚构拟合值。
- [通过] 模型没有声称已经获得参数、RMSE、最优值或通过数值验证，符合当前 model 阶段边界。
- [问题] Huber 回归的早期滞后值初始化规则属于必要计算参数，目前未封闭；不能在代码阶段临时用补零、循环填充或删除样本等不同方案任意选择。

### 可求解性
- [通过] 在候选开工集合有限且离散后，任务调度、储能、能源流和多数 \(\varepsilon\) 约束可构造成 MILP。
- [通过] 指标分母非正时输出“不可计算”并退出相应路径，没有用任意小常数制造有限结果。
- [通过] 必要锚点失败、预算超时或滚动拼接失败时结构化停止，未把部分结果伪装成正式解。
- [问题] 当前式(23)–(26)因负时间滞后量未定义而不能直接拟合。
- [问题] 当前 \(\Omega_i\) 没有显式有限整数定义；若按连续 \(s\) 理解，\(x_{irs}\) 将具有不可枚举索引，推荐的 MILP 无法直接建立。
- [问题] 问题一没有产生 \((r_i^0,s_i^0)\) 的算法，导致末端 MILP 的固定占用输入缺失。仅写“审计通过后求解”不能替代前序方案的生成。
- [通过] 对滚动时域结果只声明 best-found 和 `global_optimality_certificate=false`，没有错误声称全局最优。

### 数据可观测性
- [通过] GPU需求和GPU-hour预测标签可由实际到达数据聚合得到，MAE、RMSE和WAPE属于可观测预测误差。
- [通过] 没有对不可观测的“最优调度标签”使用准确率、召回率或混淆矩阵。
- [通过] 成本、碳排放、网络时延、新能源利用率、SOC、峰值和爬坡量均可由附件与决策轨迹复算。
- [通过] WAPE 分母为零时不强行计算，避免 NaN/Inf。
- [通过] 外部搜索状态明确为未执行，模型没有把待调研内容或所谓典型参数当作文献事实。

### 结果常识性
- [通过] 模型禁止储能同时充放电和电网同时购售电，避免非物理循环套利。
- [通过] 实时任务即时开工并受网络时延、GPU、IT功率和设施功率约束，符合工程常识。
- [通过] 固定负荷、储能终端能量、购售电上限和新能源弃电均已建模。
- [通过] 问题四的服务质量中实时开工、SLA和截止完成分量在硬约束可行解中通常恒为1，但等待分量仍可用于区分弹性任务方案；这不会使模型失效，不过报告中应说明前三项主要承担可行性审计作用。
- [问题] 若问题一忽略或无法生成前序跨界占用，最后24小时可能重复使用已被早期任务占用的 GPU 和功率容量，所得甘特图及利用率会违反实际资源状态。

## 修改建议
1. 将回归有效训练样本明确改为所有滞后均可观测的时刻，例如 \(t\ge168\)；或者预先声明唯一、可复现且不泄漏验证集信息的历史初始化规则。季节性候选也应对历史不足的时刻给出同样的有限处理规则。
2. 将候选集合改为
   \[
   \Omega_i=\{(r,s):r\in\mathcal R,\ s\in\{0,\ldots,2405\}\cap\mathbb Z,\ s\ge a_i,\ s+h_i\le F_i,\ \ell_{o_ir}\le\ell_i^{\max}\}.
   \]
   并显式要求 \(\omega_{i,2406}(s)=0\)。
3. 为问题一补充前序基础调度的生成规则：应先按同一任务、时延和瞬时容量约束，对所有可能跨越2376时点的前序任务形成唯一、可复现的基础调度；随后从该完整方案提取 \(\mathcal I^{pre}\) 和固定占用。若前序方案来自外部文件，则必须规定文件字段、完整性审计和缺失时的停止规则。
4. 在完成上述修订后，再由代码阶段计算预测误差、调度方案、锚点、路径和情景结果；当前阶段不得声称已经完成拟合或数值验证。
