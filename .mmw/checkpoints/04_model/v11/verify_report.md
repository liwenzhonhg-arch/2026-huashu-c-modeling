# 模型验证报告

## 总体评价
需修改。模型对任务不可抢占、时延与截止约束、储能 SOC、能源分流以及不可观测最优标签的处理总体严谨，但负荷与 GPU 容量公式存在量纲错误；问题四的碳约束情景参数未接入约束；购售电互斥未落实；多个子问题也未形成共享的 300 秒总执行预算和封闭的候选数量规则。这些问题会影响物理解释、情景结果或单轮可执行性，当前严重程度为 `block`。

## 逐项检查

### 公式正确性
- [问题] 式(4)中 \(g_i p_{k_i}^{GPU}q_{it}(s)\) 的单位为 MWh，而 \(P_{rt}^{AI}\) 被定义为 MW。若其表示小时平均功率，应改为
  \[
  P_{rt}^{AI}=\frac{1}{\Delta t}\sum_{i,s}g_ip_{k_i}^{GPU}q_{it}(s)x_{irs}.
  \]
  当前 \(\Delta t=1\rm h\) 时数值恰好相同，但原公式在量纲上不成立，也无法安全推广到其他步长。
- [问题] 式(5)左侧 \(\sum g_iq_{it}(s)x_{irs}\) 是 GPU·h，右侧 \(G_r\) 是 GPU，不能直接比较。按附件的 GPU-hour 口径，应写为
  \[
  \sum_{i,s}g_iq_{it}(s)x_{irs}\le G_r\Delta t.
  \]
- [问题] 式(11)的分子是 GPU·h、分母是 GPU，所得量不是无量纲百分比。应除以 \(G_r\Delta t\)。
- [通过] 重叠函数(1)、任务唯一分配、截止时点、网络时延、设施负荷换算以及 SOC 递推的符号均正确。
- [通过] 问题二式(12)–(14)和问题三式(23)–(26)的新能源分流经代数消元后均能恢复附件给出的总能量平衡，没有重复计算外送电。
- [通过] 碳排放仅按购电量计算，储能充放电效率的作用方向正确。
- [问题] 式(38)定义了碳情景参数 \(\alpha_C\)，但没有给出其与 \(\epsilon_C\) 的关系，因而“不同碳约束”情景无法按现有方程生成。至少应明确基准碳预算及
  \[
  \epsilon_C^{sc}=\alpha_C E_{\mathrm{CO2}}^{ref}
  \]
  或其他固定、可复算的映射。
- [问题] \(P_r^{peak}\) 未设置非负下界。当区域所有时段均为净外送时，模型可能把“峰值净购电功率”报告为负数。若指标含义是最大购电需求，应增加 \(P_r^{peak}\ge0\)。

### 量纲一致性
- [问题] 式(4)、式(5)和式(11)混用了 MW、MWh、GPU 与 GPU·h，是本模型最主要的量纲问题。
- [通过] 成本、碳排放、平均网络时延、SOC 动力学、爬坡量及新能源利用率的其余量纲一致。
- [通过] 式(19)、式(20)和式(32)均处理了零分母分支，不会因此产生 NaN 或 Inf。

### 约束完整性
- [通过] 任务的到达、单点执行、不可抢占、完成期限、实时即时开工、单向时延、GPU、IT 功率和设施功率约束基本完整。
- [通过] 第2406小时不安排任务、但保留电力和储能终端结算的时钟语义正确。
- [通过] 问题三固定基准 AI 负荷与非 AI 负荷，没有错误地重新优化任务调度。
- [问题] 假设20承诺在价格不能自然排除同时购售电时增加互斥约束，但问题二至四的正式约束只有购售电上下界，没有互斥变量或可验证的价格充分条件。模型可能出现同一小时同时购电和售电。应加入购售电二元状态，或在读取数据后验证全部时段均满足足以排除套利的价格条件。
- [问题] 滚动窗口只说明传递“已开工任务”，没有明确固定已经承诺但尚未开工的任务决策。每窗固定前6小时意味着该区间内已确定区域和开工时刻的全部任务都应冻结，否则后续窗口可能改写先前承诺。
- [问题] 问题四联合储能滚动优化没有给出窗口末端 SOC 可达域或其他终端可行性保护。早期窗口可能耗尽能量，使最终 \(E_{r,2406}\ge E_r^0\) 在后续窗口才暴露为不可行。可以使用保守的剩余最大可充电量约束，或让窗口保留通向最终 SOC 的可达性约束。
- [问题] 问题二、三、四的 \(\epsilon_C,\epsilon_L,\epsilon_U,\epsilon_{P,r},\epsilon_{V,r},\epsilon_Q\) 候选集合和生成数量没有封闭定义，无法确定需要求解多少个 MILP，也无法复现 Pareto 扫描。

### 参数合理性
- [通过] 24小时窗口、6小时承诺、18小时重叠以及300秒外部总超时与15秒尾部预留本身符合给定运行接口。
- [问题] 300秒预算仅在问题四内部定义。问题一的预测与调度、问题二扫描、问题三扫描、问题四联合优化、验证和文件输出没有共享同一次执行的总墙钟预算。若这些任务由一次 Coder 调用完成，现有预算分配会超过共同上限。
- [问题] 问题四可能包含多组 Pareto 候选和最多 \(3^3=27\) 个情景，但没有固定候选上限、优先级或截止前逐候选门禁规则，不能证明能在285秒搜索截止前完成必答部分。
- [通过] 未把“未执行外部搜索”的内容冒充文献参数，也没有声称已经得到拟合参数、RMSE、最优值或通过数值验证。
- [通过] 新能源扰动保持非负，但代码阶段还应固定随机数生成器及区域—时刻生成顺序，才能实现跨环境复现。

### 可求解性
- [通过] 在修正量纲并补齐互斥后，各子模型原则上可表述为岭回归、MILP或一组有限的 \(\epsilon\)-约束 MILP。
- [问题] 当前没有预声明有限的 Pareto 网格、情景求解顺序和候选总数，单轮计算规模不封闭。
- [问题] 预算没有覆盖四问的共同执行过程，违反共享总时长要求。应从同一个 \(t_{\mathrm{start}}\) 建立 \(D_{\mathrm{search}}=t_{\mathrm{start}}+285\rm s\)，并为预测标定、问题一调度、问题二固定扫描、问题三、问题四、验证和输出共同分配预算。
- [问题] “固定必答工作若超时则结构化失败”可以诚实停止，但不能替代启动前的可执行规模设计。必须预先规定各子问题的固定候选数或按剩余时间计算的封闭上限，并在每个候选启动前检查共同截止时间。
- [通过] 有限解状态、不可行情景和零分母状态的输出设计合理，不会强行输出 NaN、Inf 或不完整解。

### 数据可观测性
- [通过] 预测任务使用实际 GPU 到达需求作为真实标签，可计算 MAE、RMSE 和 WAPE。
- [通过] 调度和储能没有真实“最优动作标签”，模型没有错误使用准确率、召回率或混淆矩阵，而是使用约束残差、守恒、求解状态和指标复算验证。
- [通过] 对 WAPE 和其他比率的零分母进行了结构化处理。
- [问题] “有限预测率”没有数学定义。若作为正式评价指标，应明确分子、分母和零值处理；否则只保留 MAE、RMSE及可计算分组的 WAPE。
- [通过] 调研证据状态诚实标为未执行外部搜索，模型正文没有将未检索事项写成已有文献事实。

### 结果常识性
- [通过] 实时任务即时开工、训练任务可延后、设施负荷受 IT 和设施容量双重约束、储能禁止同时充放电等设定符合工程常识。
- [问题] 购售电互斥只出现在文字假设中，未进入正式方程，可能产生同小时购售电或通过电网购电替代本地负荷、同时外送新能源的非预期策略。
- [问题] 若没有 \(P_r^{peak}\ge0\)，区域“峰值净购电”可能为负，不符合通常的峰值购电容量解释。
- [问题] 问题四前三个服务质量分量已被硬约束固定为1，服务质量权衡实际上主要只剩等待得分；这不会使模型不可解，但应在结果中说明该指标退化，避免宣称获得了四个独立维度的服务质量权衡。

## 修改建议

1. 在所有 GPU-hour 和功率公式中显式保留 \(\Delta t\)：式(4)除以 \(\Delta t\)，式(5)右侧乘 \(\Delta t\)，式(11)分母改为 \(G_r\Delta t\)。
2. 明确碳情景的参考量和映射，例如 \(\epsilon_C^{sc}=\alpha_C E_{\mathrm{CO2}}^{ref}\)，并说明参考排放来自哪个固定可行方案。
3. 将购售电互斥落实为正式约束；若选择依靠价格排除，必须给出并逐时验证充分条件。
4. 增加 \(P_r^{peak}\ge0\)，并明确峰值指标是 \(\max_t\max(0,N_{rt})\) 还是纯粹的 \(\max_tN_{rt}\)。
5. 滚动窗口应冻结所有已承诺决策，不仅是已开工任务；联合储能窗口还应加入通向终端 SOC 的剩余可达性约束。
6. 为所有 \(\epsilon\) 网格、Pareto候选和27种情景规定有限候选集、固定顺序及候选上限。
7. 四个子问题应共享同一 \(B_{\mathrm{total}}=300\rm s\) 和 \(D_{\mathrm{search}}=t_{\mathrm{start}}+285\rm s\)，在每次模型启动前检查剩余预算，并为验证与文件输出保留15秒。
8. 将“有限预测率”补充为可计算的明确公式，或从正式指标中删除。
